## เริ่มใช้งาน

```bash
npm install
```

```bash
cp .env.example .env
```

```bash
npm run migrate
```

```bash
npm start
```

| คำสั่ง | หน้าที่ |
|---|---|
| `npm run dev` | รันแบบ auto-reload ตอนแก้โค้ด |
| `npm run migrate` | สร้าง schema + ข้อมูลตั้งต้น (รันซ้ำได้ ไม่ทับข้อมูลเดิม) |
| `npm run reset` | ลบตารางทั้งหมดแล้วสร้างใหม่ |

## ฐานข้อมูล

โค้ดใช้ SQL ของ PostgreSQL ล้วน แล้วเลือก driver ตอนรัน

| เงื่อนไข | ตัวที่ใช้ |
|---|---|
| ตั้ง `DATABASE_URL` | PostgreSQL จริงผ่าน `node-postgres` |
| ไม่ตั้ง | **PGlite** — PostgreSQL คอมไพล์เป็น WASM รันในตัวแอป เก็บไฟล์ที่ `./data/pglite` |

PGlite มีไว้ให้พัฒนาและทดสอบได้โดยไม่ต้องติดตั้งอะไรเพิ่ม SQL ชุดเดียวกันย้ายขึ้น PostgreSQL จริงได้โดยไม่ต้องแก้

> **ขึ้น production ต้องใช้ PostgreSQL จริง** PGlite เปิดได้ครั้งละหนึ่งโปรเซส ไม่มี replication และไม่มีเครื่องมือสำรองข้อมูลมาตรฐาน
> ห้ามวางไดเรกทอรีข้อมูลไว้ในโฟลเดอร์ที่มีตัวซิงก์ไฟล์ (OneDrive, Dropbox) เพราะการซิงก์ระหว่างเขียนทำให้ไฟล์เสียหายได้

ตาราง `readings` แบ่ง partition รายเดือน สร้างล่วงหน้า 3 เดือนตอนบูตและวันละครั้ง
partition ที่เก่ากว่า `retention.raw_months` (ค่าเริ่มต้น 12 เดือน) จะถูกลบอัตโนมัติ

## การเข้าสู่ระบบ

**LINE Login** เป็นทางหลักตามสเปค ต้องกรอก `LINE_LOGIN_CHANNEL_ID` และ `LINE_LOGIN_CHANNEL_SECRET`
และตั้ง Callback URL ใน LINE Developers Console ให้ตรงกับ `LINE_LOGIN_CALLBACK_URL`

**โหมดพัฒนา** เมื่อ `DEV_LOGIN=true` หน้า login จะมีช่องกรอกรหัสพนักงานเข้าระบบตรง ๆ โดยข้าม LINE
ใช้ทดสอบเท่านั้น — ระบบจะปฏิเสธการบูตถ้าเปิดค่านี้ไว้พร้อมกับ `NODE_ENV=production`

**โหมดผู้ดูแลระบบ** ผู้ใช้ที่มีธง `is_admin` กดปุ่ม "จัดการระบบ" แล้วกรอกรหัส Admin
สิทธิ์มีผลเฉพาะ session นั้นและหมดอายุเมื่อไม่มีการใช้งาน 30 นาที
รหัสตั้งต้นคือ `Admin173` และ `Admin1173` **เก็บเป็น hash แบบ scrypt ไม่ได้อยู่ในโค้ด**
เปลี่ยนได้จากหน้าตั้งค่าระบบ และควรเปลี่ยนทันทีหลังติดตั้ง

## การอ่านค่าจาก PLC ผ่าน Modbus TCP

ระบบอ่าน holding register จาก PLC โดยตรง ไม่ต้องมี Node-RED คั่นกลาง **รองรับหลาย PLC พร้อมกัน**
(จุดวัดคนละอันใช้คนละ PLC ได้ — เช่นตู้ควบคุมคนละอาคารคนละ IP) เปิดใช้งานใน `.env` แล้วรีสตาร์ต

```bash
MODBUS_ENABLED=true
MODBUS_POLL_MS=1000
```

เปิด Modbus แล้วตัวจำลองข้อมูลจะหยุดเองอัตโนมัติ เพื่อไม่ให้ค่าปลอมปนกับค่าจริง

### PLC และ address ของแต่ละจุดวัด

IP/port ของแต่ละ PLC ไม่ได้อยู่ใน `.env` อีกต่อไป แต่เก็บในตาราง `plcs` — **เพิ่ม/แก้/ลบ PLC ได้จากการ์ด
"PLC" ในหน้า "จุดวัดและ setpoint" โดยไม่ต้องรีสตาร์ต** จากนั้นแต่ละจุดวัดในตาราง `sensors` เลือกได้ว่าจะ
อ่านผ่าน PLC ตัวไหน (`plc_id`) พร้อม address/unit-id/FC ของตัวเอง — แก้ได้จากปุ่ม "Modbus" ในแถวของจุดวัดนั้น
ค่าตั้งต้นตรงกับที่ตั้งไว้ใน Node-RED เดิม คือ Unit-Id 1, FC 3, เริ่มที่ address 528 บน PLC ตัวแรก

| ช่อง | จุดวัด | Address |
|---|---|---|
| AI1 | LT-1A | 528 |
| AI2 | LT-1B | 529 |
| AI3 | LT-2 | 530 |
| AI4 | LT-3 | 531 |
| AI5 | LT-4 | 532 |
| AI6 | LT-5 | 533 |
| AI7 | LT-600Q | 534 |
| — | TT-05, FT-600Q, PT-AIR, PT-STM | **ยังไม่ได้กำหนด** |

จุดวัดที่ยังไม่ได้กรอก address จะไม่ถูกอ่าน และจะขึ้นแจ้งเตือน "ขาดสัญญาณ"
ซึ่งเป็นสัญญาณให้เห็นทันทีว่ายังตั้งค่าไม่ครบ

### การแปลงค่า

`ค่าจริง = ค่าดิบจาก register × scale + offset` ตั้งค่าเริ่มต้นเป็น `scale = 1` คือใช้ค่าดิบตรง ๆ
ถ้า PLC ส่งระดับน้ำมาเป็น 0–10000 แทน 0–100 ให้ตั้ง scale เป็น `0.01`

หน้าตั้งค่ามีปุ่ม **ทดสอบอ่านค่า** ที่ยิงไปที่ PLC จริงแล้วแสดงทั้งค่าดิบและค่าหลังคูณ scale
โดยไม่บันทึกลงฐานข้อมูล ใช้หา address และ scale ที่ถูกต้องได้โดยไม่กระทบข้อมูลจริง

รองรับ `uint16`, `int16`, `uint32`, `int32`, `float32` และสลับลำดับ word สำหรับ PLC ที่เรียงกลับด้าน

### พฤติกรรมที่ออกแบบไว้

- register ที่อยู่ติดกันถูกรวมเป็นคำสั่งเดียว — 7 บ่อใช้คำสั่งอ่านเพียงคำสั่งเดียวต่อรอบ ไม่ใช่ 7 คำสั่ง
- สายหลุดแล้วต่อกลับเองทุก 5 วินาที และเกิดแจ้งเตือน "ขาดสัญญาณ" ระดับวิกฤตตามเวลาที่ตั้งไว้
- เมื่อขาดสัญญาณ แจ้งเตือนที่อิงค่าล่าสุดของจุดวัดนั้นจะถูกปิด เพราะค่าเดิมเชื่อถือไม่ได้แล้ว
- ค่าที่อ่านได้แต่หลุดพิสัยของเครื่องมือวัดจะถูกบันทึกด้วย `quality = 0` และไม่นำไปสร้างแจ้งเตือน
  กันกรณีช่องสัญญาณขาดแล้ว PLC คืนค่าสุดสเกล

### ทดสอบโดยไม่ต้องต่อ PLC จริง

```bash
node tools/fake-plc.js 5502 528
```

แล้วเพิ่ม PLC ในหน้า "จุดวัดและ setpoint" โดยตั้ง IP เป็น `127.0.0.1` และ port เป็น `5502`

## ทางเลือก: ส่งค่าเข้าทาง HTTP

ถ้ามี gateway ที่ push ข้อมูลเองอยู่แล้ว ใช้ทางนี้แทน Modbus ได้ โดยตั้ง `MODBUS_ENABLED=false`

```
POST /api/ingest
Authorization: Bearer <INGEST_TOKEN>
```

รองรับสองรูปแบบ

```json
{ "ts": "2026-09-07T14:32:00+07:00",
  "readings": [ { "tag": "LT-2", "value": 91.4, "quality": 1 } ] }
```

```json
{ "ts": "2026-09-07T14:32:00+07:00",
  "values": { "LT-2": 91.4, "TT-05": 38.2 } }
```

ส่ง `quality: 0` เมื่อค่าที่อ่านได้น่าสงสัย ระบบจะบันทึกไว้แต่ไม่นำไปสร้างแจ้งเตือน

## การแจ้งเตือน

เกิดเมื่อค่าหลุด LL/HH ต่อเนื่องครบ `debounce_sec` ของจุดวัดนั้น (ค่าเริ่มต้น 60 วินาที)
หนึ่ง tag + เงื่อนไข มีแจ้งเตือนที่ยังไม่คืนสภาพได้ครั้งละหนึ่งรายการ บังคับด้วย unique index ในฐานข้อมูล
ระบบส่งข้อความย้ำทุก 30 นาทีหากยังไม่มีใครรับทราบ และส่งข้อความปิดเรื่องเมื่อค่ากลับเข้าช่วง

ผู้ใช้จะได้รับข้อความก็ต่อเมื่อครบสามข้อ: ผูกบัญชี LINE แล้ว + เป็นเพื่อนกับ OA + เปิดรับแจ้งเตือน
ถ้ายังไม่ครบ หน้าหลักจะขึ้นแถบเตือนพร้อม QR และลิงก์เพิ่มเพื่อน และหน้าตั้งค่าส่วนตัวจะแสดง QR ขนาดใหญ่กว่า
QR อ่านจาก `public/img/QRcodeLine.png` (เปลี่ยนที่อยู่ได้ด้วย `LINE_OA_QR_URL`) ถ้าไม่มีไฟล์จะซ่อนส่วนนี้ไปเอง

สถานะ "เป็นเพื่อนกับ OA" มาจาก webhook `follow` / `unfollow` เป็นหลัก แต่ webhook ส่งมาถึงได้ต่อเมื่อ
เซิร์ฟเวอร์มี URL สาธารณะแบบ HTTPS ตอนรันบน localhost จึงยังไม่มี event เข้ามา ระบบจึงถาม LINE ตรง ๆ ด้วย
`GET /v2/bot/profile/{userId}` เพิ่มอีกทางในจังหวะเข้าสู่ระบบและตอนผูกรหัสพนักงาน และมีปุ่ม
"ตรวจสถานะอีกครั้ง" ในหน้าตั้งค่าส่วนตัว (`POST /api/me/check-friend`) ให้ผู้ใช้สั่งตรวจเองได้

ปุ่ม "รับทราบการแจ้งเตือน" ในข้อความ LINE เปิดผ่าน LIFF ซึ่งส่ง `?alarm=<id>` มาเป็น query
`public/js/app.js` จะแปลงเป็น `#/alarms?id=<id>` แล้วเปิดรายละเอียดแจ้งเตือนนั้นให้อัตโนมัติ

เมื่อยังไม่ได้ตั้งค่า LINE Messaging API ระบบยังทำงานครบทุกอย่าง แต่บันทึกใน `notification_log`
ว่าใครควรได้รับพร้อมเหตุผลที่ยังไม่ส่ง ดูได้จากหน้าตั้งค่าระบบ

## ก่อนขึ้น production

- [ ] ตั้ง `NODE_ENV=production` (ระบบจะตรวจค่าที่จำเป็นให้เอง และปฏิเสธการบูตถ้าขาด)
- [ ] ใช้ PostgreSQL จริงผ่าน `DATABASE_URL` ไม่ใช่ PGlite
- [ ] สุ่ม `SESSION_SECRET` และ `INGEST_TOKEN` ใหม่ — `node -e "console.log(require('crypto').randomBytes(48).toString('base64url'))"`
- [ ] `DEV_LOGIN=false` และ `SIMULATE=false`
- [ ] เปลี่ยนรหัส Admin จากค่าตั้งต้นทันทีหลังติดตั้ง
- [ ] วางหลัง HTTPS reverse proxy — cookie ตั้ง `Secure` อัตโนมัติเมื่อเป็น production
- [ ] แทนค่า LL/HH ทั้งหมดด้วยค่าจริงจากหน้างาน
- [ ] ตั้งการสำรองข้อมูลรายวันและทดสอบกู้คืน

**ข้อจำกัดที่ควรรู้:** ตัวนับ rate limit ของการผูกรหัสพนักงานและการยืนยันรหัส Admin
เก็บในหน่วยความจำของโปรเซส ถ้าจะขยายเป็นหลาย instance ต้องย้ายไปเก็บใน Redis หรือฐานข้อมูล
