# การออกแบบตู้ควบคุมและการเชื่อมต่อ PLC (Siemens LOGO! + AM2) กับระบบ Water Monitoring

เอกสารนี้ใช้ประกอบการเดินสายตู้ควบคุมภาคสนาม และอธิบายเส้นทางข้อมูลตั้งแต่เซนเซอร์วัดระดับน้ำ 4-20mA
ผ่าน Siemens LOGO! + โมดูลขยายอนาล็อก AM2 ไปจนถึงเว็บแดชบอร์ดของโปรเจกต์นี้ผ่าน Modbus TCP

> **ข้อสมมติที่ใช้ในเอกสาร** (ปรับตามอุปกรณ์จริงที่มีหน้างาน):
> - LOGO! รุ่นมี Ethernet ในตัว (0BA7/0BA8 เช่น LOGO! 12/24RCE, 24CE) ที่รองรับ Modbus TCP Server และเว็บเซิร์ฟเวอร์ในตัว
> - โมดูลขยาย LOGO! AM2 จำนวน 1 ตัว ต่อเซนเซอร์ระดับน้ำแบบ 2-wire (loop powered) 4-20mA ได้สูงสุด 2 จุดวัดต่อโมดูล
> - แหล่งจ่ายไฟหลักเป็น 24VDC (ถ้าใช้ LOGO! รุ่น AC ให้ปรับผังไฟ AC ส่วนอินพุตตามจริง)
> - เลขขั้วต่อ (terminal) ของ AM2 ในเอกสารนี้เป็นตัวอย่างมาตรฐานทั่วไป **ต้องตรวจสอบกับคู่มือ/แผ่นป้ายรุ่นที่มีจริงก่อนเดินสายทุกครั้ง**

## 1. ภาพรวมเส้นทางข้อมูล (Data Flow)

```
เซนเซอร์วัดระดับน้ำ (4-20mA, 2-wire)
        │  สายสัญญาณ shielded twisted pair
        ▼
LOGO! AM2 (analog input, สเกล 0-1000)
        │  โปรแกรมใน LOGO!Soft Comfort: แปลงค่าดิบ → หน่วยวิศวกรรม → เขียนลง VM
        ▼
LOGO! base (Ethernet, Modbus TCP Server, unit id = 1)
        │  Modbus TCP  (FC3 Read Holding Registers)  ผ่านสวิตช์ในตู้/LAN โรงงาน
        ▼
Node.js server (server/services/modbusPoller.js → modbusClient.js)
        │  raw × modbus_scale + modbus_offset → บันทึกลง PostgreSQL
        ▼
เว็บแดชบอร์ด (public/) + แจ้งเตือนผ่าน LINE
```

ระบบฝั่งซอฟต์แวร์ของโปรเจกต์นี้ **เป็นฝ่าย poll (client)** เข้าไปอ่านค่าจาก LOGO! (server) เป็นระยะทุก
`MODBUS_POLL_MS` มิลลิวินาที (ค่าเริ่มต้น 1000ms) — ไม่มีการเขียนค่าใด ๆ กลับไปที่ PLC (อ่านอย่างเดียว
ตามที่ออกแบบไว้ใน `modbusClient.js`)

## 3. ผังไฟเลี้ยง (Power Wiring)

```
L (220VAC) ──┬── MCB ── Switching PSU 220VAC→24VDC ──┬── 24V+ bus ──► LOGO! (L+) 
N (220VAC) ──┘                                        └── 0V  bus ──► LOGO! (M)
PE ───────────────────────────────────────────────────────────────► Ground bar ► ตู้/ชีลด์สาย
                                                       24V+ bus ──► AM2 (L+)   [ถ้ารุ่นต้องไฟแยก]
                                                       0V  bus ──► AM2 (M)
                                                       24V+ bus ──► loop 4-20mA (ผ่านเซนเซอร์)
```

**ข้อควรระวัง**
- แยกบัส 24VDC เส้นสัญญาณ (loop 4-20mA) ออกจากบัสที่จ่ายให้อุปกรณ์กำลัง เช่น solenoid/คอนแทกเตอร์ เพื่อลด noise
- ต่อกราวด์ตู้ (PE) และปลอกชีลด์ของสาย 4-20mA เข้ากราวด์บาร์จุดเดียว (ฝั่ง PLC) เท่านั้น ป้องกัน ground loop
- ติดป้ายชื่อสาย (wire marker) ทุกเส้นตามชื่อจุดวัด (tag) ให้ตรงกับชื่อ tag ที่จะตั้งค่าในเว็บแอป

## 4. การต่อเซนเซอร์ 4-20mA เข้า AM2 (2-wire loop)

เซนเซอร์ 2-wire (loop powered) ไม่มีขั้วไฟเลี้ยงแยก กระแส 4-20mA ที่เซนเซอร์ปรับค่าตามระดับน้ำ
จะไหลเป็นวงเดียวกับไฟเลี้ยง ผังการต่อสายมาตรฐาน:

```
24V+ (จาก PSU) ──► เซนเซอร์ [+ supply] 
เซนเซอร์ [- signal] ──► AM2 ช่อง I1 (analog in) 
AM2 M (common) ──► 0V (กลับ PSU)
```

ตัวอย่างขั้วต่อ AM2 (**ตรวจสอบกับคู่มือรุ่นจริงก่อนต่อ**):

| ขั้วบน AM2 | ต่อกับ | ชนิดสาย |
|---|---|---|
| L+ | 24VDC จาก PSU (ไฟเลี้ยงโมดูล) | สายไฟ 1.0-1.5 mm² |
| M | 0V จาก PSU (common) | สายไฟ 1.0-1.5 mm² |
| I1 | ขั้ว signal (-) ของเซนเซอร์จุดที่ 1 | shielded twisted pair, ปลอกชีลด์ลงกราวด์ฝั่งตู้ด้านเดียว |
| I2 | ขั้ว signal (-) ของเซนเซอร์จุดที่ 2 (ถ้ามี) | shielded twisted pair |

ขั้นตอนก่อนจ่ายไฟจริง:
1. ตั้งโหมดของแต่ละช่อง I1/I2 เป็น **กระแส (4-20mA)** ไม่ใช่แรงดัน (0-10V) — บางรุ่นตั้งด้วย DIP switch
   บนตัวโมดูล บางรุ่นตั้งด้วยพารามิเตอร์ตอนวางบล็อก AM2 ใน LOGO!Soft Comfort
2. วัด continuity/ตรวจขั้ว +/- ของเซนเซอร์กับ datasheet ก่อนจ่ายไฟ ต่อผิดขั้วมักไม่พังแต่จะอ่านค่าไม่ได้
3. จ่ายไฟแล้ววัดกระแส loop ด้วยมัลติมิเตอร์ (ต่ออนุกรม หรือใช้ clamp DC) เทียบกับระดับน้ำจริงก่อนเชื่อม LOGO!

## 5. การแปลงค่าใน LOGO!Soft Comfort

ค่าอนาล็อกดิบจาก AM2 จะอยู่ในช่วง **0–1000** (เทียบเป็นเส้นตรงกับช่วง 4–20mA ที่ตั้งไว้) ก่อนส่งออกทาง
Modbus ควรใช้บล็อกแปลงค่า (เช่น Analog Amplifier / Analog conversion) ใน LOGO!Soft Comfort แปลงจาก
0–1000 → หน่วยวิศวกรรมจริงคูณ 100 (เก็บทศนิยม 2 ตำแหน่งเป็นจำนวนเต็ม) แล้วจึงเขียนผลลัพธ์ลง VM word
ที่จะ map ออกเป็น Modbus register เช่น

```
ระดับน้ำจริง (0.00–5.00 ม.) × 100  →  เก็บเป็น 0–500 ใน VM word
```

การทำเช่นนี้ทำให้ฝั่งเว็บแอปตั้งค่าได้ตรงกับรูปแบบที่ระบบใช้อยู่แล้ว (ดูหัวข้อ 6.2)

## 6. การตั้งค่า Modbus TCP

### 6.1 ฝั่ง LOGO! (Server)

1. ใน LOGO!Soft Comfort เปิดหน้าตั้งค่าเครือข่าย ตั้ง IP ของ LOGO! ให้อยู่วง LAN เดียวกับเครื่องที่รัน
   โปรเจกต์นี้ — ของหน้างานนี้คือ `192.168.0.3 / 255.255.255.0`
2. เปิดใช้งาน Modbus TCP Server (network configuration ของ LOGO! 8) กำหนดช่วง VM ที่จะ expose —
   โปรแกรมจะสร้างตารางที่บอกว่า VM byte address ใดตรงกับ Modbus register หมายเลขใด **ให้บันทึกเลข
   register จริงจากตารางนี้** เพราะจะต้องใช้กรอกในเว็บแอป (ห้ามเดา/คาดคะเนเลขที่อยู่เอง)
3. Unit ID เริ่มต้นใช้ `1` (LOGO! ไม่ได้อิง unit id หลายค่าเหมือน gateway บางยี่ห้อ)
4. จำกัดจำนวนการเชื่อมต่อ Modbus TCP พร้อมกัน — ให้มีเซิร์ฟเวอร์โปรเจกต์นี้เพียงตัวเดียวที่ต่อเข้าไป
   อ่านค่า (poll) เพื่อไม่ให้ LOGO! ปฏิเสธการเชื่อมต่อ

### 6.2 ฝั่งเว็บแอป (Client — โปรเจกต์นี้)

ตั้งค่าใน `.env` (อ้างอิง `.env.example`) — **IP ของ LOGO! ไม่ได้อยู่ใน `.env` แล้ว** เพราะระบบรองรับ
หลาย PLC พร้อมกัน (แต่ละจุดวัดเลือกได้ว่าจะอ่านผ่าน PLC ตัวไหน) IP จึงย้ายไปตั้งจากหน้าเว็บแทน (ดูข้อ 6.3):

```
MODBUS_ENABLED=true
MODBUS_POLL_MS=1000
MODBUS_TIMEOUT_MS=3000
MODBUS_RECONNECT_MS=5000
```

เปิด `MODBUS_ENABLED=true` แล้วตัวจำลองข้อมูล (`simulate`) จะปิดเองอัตโนมัติ (`server/config.js`)

จากนั้นในหน้าจอ "จุดวัดและ setpoint" ของเว็บแอป การ์ด "PLC" ด้านบนสุดจะมี PLC ชื่อ `PLC-1` ที่ IP
`192.168.0.3` (หน้างานนี้) ให้อยู่แล้ว — ถ้ายังไม่มีให้กด "+ เพิ่ม PLC" แล้วกรอก IP/port ตามหน้างานจริง
จากนั้นตั้งค่า tag **`LT-600Q`** (ระดับน้ำ บ่อ 600Q) ให้ตรงกับค่าที่ยืนยันแล้วจากหน้างานจริง:

| ฟิลด์ | ค่า | ที่มา |
|---|---|---|
| `plc_id` | PLC ที่ IP `192.168.0.3` | เลือกจาก dropdown "PLC" ในหน้าต่างตั้งค่า Modbus ของจุดวัดนี้ |
| `modbus_unit_id` | `1` | ยืนยันแล้วจากการทดสอบอ่านจริงที่ 192.168.0.3 |
| `modbus_fc` | `4` (Read Input Registers) | **ยืนยันแล้ว** — FC3 (holding register) คืนค่า 0 ทุก address, FC4 คืนค่าจริง |
| `modbus_address` | `0` | **ยืนยันแล้ว** ด้วยการเปลี่ยนระดับน้ำจริงแล้ว poll ซ้ำ: ค่าขยับจาก 707 → 622–623 ตามระดับน้ำที่เปลี่ยน (ไม่ใช่ค่าคงที่/noise) |
| `modbus_data_type` | `uint16` | ค่า register เดียว (16 บิต) — ไม่ต้องแปลงหน่วยในโปรแกรม LOGO! เลย ใช้ raw ตรงจาก AM2 |
| `modbus_scale` | **`-0.6`** | ผู้ดูแลระบบยืนยันสเกลของบ่อ 600Q: raw `0` → `600Q`, raw `1000` → `0Q` (เซนเซอร์วัดกลับด้าน — ยิ่งน้ำเยอะ raw ยิ่งน้อย) |
| `modbus_offset` | **`600`** | คำนวณจากสูตร `ปริมาณน้ำ (Q) = raw × (-0.6) + 600` — ตรวจ: raw=0→600Q ✓, raw=1000→0Q ✓ |
| `modbus_word_swap` | ปิด | ใช้เฉพาะค่า 32 บิตที่ word สลับกัน (uint32/int32/float32) |
| `range_min` / `range_max` | `0` / `600` | หน่วย Q ตามพิสัยจริงของบ่อ (ปรับจากค่า default 0–100 เดิมในระบบ) |

> **ผลทดสอบจริง (2026-09-12, unit id 1, host 192.168.0.3, tag `LT-600Q`):**
> - รอบแรก: FC4 address `0` = `707` (นิ่งระหว่าง 2 ครั้งที่อ่านห่างกัน 1.5 วิ)
> - หลังเปลี่ยนระดับน้ำจริงแล้ว poll ซ้ำ 10 ครั้ง (ห่างกัน ~1.2 วิ): ค่าลดลงเหลือ `622–623` (นิ่ง ±1) — **ยืนยันว่า address นี้คือช่องวัดระดับน้ำจริง ไม่ใช่ค่าคงที่**
> - address `1` = `4`–`5` (สั่นเล็กน้อย) น่าจะเป็นช่องที่ 2 หรือค่าที่ไม่ได้ใช้งาน — address `2`–`19` = `0` ทั้งหมด
> - หน่วย "Q" ที่ผู้ดูแลระบบระบุ (0–600 ที่ raw 1000–0) สันนิษฐานว่าหมายถึงปริมาตรน้ำ (ลูกบาศก์เมตร/คิว) ในบ่อ — ควรยืนยันหน่วยที่แท้จริงกับผู้ดูแลระบบอีกครั้งหากนำไปใช้แสดงผลบนเว็บ

**หมายเหตุ:** ค่าในตารางนี้ยังไม่ได้เขียนเข้าฐานข้อมูลจริงของระบบ (sensors table มีตัว server ที่รันอยู่ถือ connection ไว้อยู่ การเขียนข้อมูลควรผ่าน `PUT /api/sensors/LT-600Q/modbus` ในหน้า "จุดวัด" ของเว็บแอปเท่านั้น ไม่ควรต่อฐานข้อมูลตรงจากภายนอกขณะ server กำลังทำงาน) — ดูหัวข้อ 6.3

ทดสอบด้วยปุ่ม **"ทดสอบอ่านค่า"** ในหน้าจุดวัด (เรียก `testRead` ใน `modbusPoller.js`) เพื่อยืนยันว่า
address/data type ที่กรอกอ่านค่าได้ตรงกับที่วัดจากมัลติมิเตอร์จริงในข้อ 4 ก่อนเปิดใช้งานจริง

### 6.3 วิธีบันทึกค่านี้เข้าระบบจริง

ระบบมี endpoint สำหรับแก้ค่า Modbus ต่อจุดวัดอยู่แล้วที่ `PUT /api/sensors/LT-600Q/modbus`
(สิทธิ์ระดับ engineer ขึ้นไป, ดู `server/routes/sensors.js`) รับ field ตรงกับตารางด้านบน
(`plc_id, modbus_unit_id, modbus_fc, modbus_address, modbus_data_type, modbus_scale, modbus_offset, modbus_word_swap`)
ส่วน PLC เอง (ชื่อ/IP/port) จัดการผ่าน `GET/POST /api/plcs`, `PUT/DELETE /api/plcs/:id` (ดู `server/routes/plcs.js`)
วิธีที่ถูกต้องคือตั้งค่าผ่าน**หน้า "จุดวัด" ของเว็บแอป** (ล็อกอินระดับ engineer) แล้วกรอกค่าตามตารางข้างต้น —
**อย่า**ต่อเข้าไฟล์ฐานข้อมูล (`data/pglite`) โดยตรงจากภายนอกขณะที่ `server/index.js` กำลังทำงานอยู่
เพราะ pglite เป็น embedded Postgres ที่ตัว server ถือการเชื่อมต่อไว้อยู่แล้ว การเปิด process ที่สองมาต่อพร้อมกัน
มีความเสี่ยงที่จะชนกันจนข้อมูลเสียหาย

หมายเหตุ: field `range_min`/`range_max` ยังไม่มี endpoint แก้ไขโดยตรงในระบบ (endpoint ที่มีตอนนี้แก้ได้แค่
`ll/hh/ll_critical/hh_critical/debounce_sec/is_active` ผ่าน `/api/sensors/:tag/setpoints`) — ต้องแก้ผ่าน
migration/DB โดยตรงเมื่อ server หยุดทำงานเท่านั้น หรือเพิ่ม endpoint ใหม่หากต้องการแก้ผ่านหน้าเว็บ

## 7. Checklist ก่อนเปิดใช้งานจริง

- [ ] ตรวจแรงดันไฟเลี้ยง 24VDC ที่ L+/M ของ LOGO! และ AM2 อยู่ในช่วง 20.4–28.8V (ตามสเปก LOGO!)
- [ ] ตั้งโหมด I1/I2 บน AM2 เป็นกระแส (mA) ถูกต้องก่อนจ่ายไฟเซนเซอร์
- [ ] วัดกระแส loop ตรงกับระดับน้ำจริง (4mA = ระดับต่ำสุด, 20mA = ระดับสูงสุด ตาม datasheet เซนเซอร์)
- [ ] ปลอกชีลด์สายสัญญาณลงกราวด์จุดเดียว (ฝั่งตู้) ไม่ลงทั้งสองปลาย
- [ ] LOGO! ต่อ LAN เดียวกับเซิร์ฟเวอร์ ping ได้จากเครื่องที่รัน `server/index.js`
- [ ] ตาราง Modbus register จาก LOGO!Soft Comfort ตรงกับค่าที่กรอกในหน้าจุดวัดของเว็บแอป
- [ ] ทดสอบอ่านค่าแล้วเทียบกับค่าจริงหน้างาน ก่อนตั้ง `range_min`/`range_max` และเปิดแจ้งเตือน
- [ ] ปิดตัวจำลองข้อมูล (`SIMULATE`) และยืนยันค่าที่เข้าระบบเป็นค่าจริงจาก PLC ไม่ใช่ค่าจำลอง
